# OpenScanner Google급 검색엔진 표준 (Google-Class Search Standard)

- 문서 번호: OP-STD-GOOGLE-CLASS-001
- 상태: 활성 (Active) — 목표 표준 + 현황 대조표
- 최초 발행: 2026-11-24
- 단일 상태 기준: [GAP_REGISTER.md](GAP_REGISTER.md). 본 문서는 목표치와 갭을 정의하고, 진행 상태는 GAP_REGISTER가 유일 기준으로 기록한다.

> 용어 규칙 (AGENTS.md·CODEX_MASTER_PROMPT.md 준수): 본 문서의 "Google급"은
> Google과 1:1 동일·동등하다는 주장이 아니라, 상용 범용 검색엔진이 갖춰야 할
> **공학적 품질 기준(수집 규모·신선도·관련도·지연·가용성·평가 방법)**을 말한다.
> 모든 "현재" 수치는 증거 링크가 있는 실측만 기재하고, 목표치는 **목표(TARGET)** 로
> 명시한다. 달성하지 못한 목표를 달성 수치처럼 표기하지 않는다.

## 2. 영역별 Google급 기준

### 2.1 수집 (Crawl)

Google급 수집의 기준은 규모가 아니라 **정책 준수 + 신선도 + 커버리지의 균형**이다.

- TARGET-C1: `robots.txt`(RFC 9309)·`noindex`·`X-Robots-Tag`·canonical 준수를 회귀 테스트로 상시 보장한다. (현재: 구현됨, `robots.go`·`extractor.go`)
- TARGET-C2: 호스트별 politeness(지연·동시성·쿼터·백오프)를 운영 지표로 관측한다. (현재: 구현됨, 대시보드 연동 잔여 039·096)
- TARGET-C3: 승인·권리 확보 호스트부터 수집을 확장하고, 수집량(페이지/일)·실패율·robots 차단율을 SLO로 둔다. (현재: allowlist 게이트 + bounded 코퍼스, 규모 확장 미실시)
- TARGET-C4: 중요 페이지 재수집 주기 목표(예: 24h)를 두고 freshness를 측정한다. (현재: freshness 스케줄러 뼈대 C-1, 실측 잔여)
- TARGET-C5: 렌더링 필요 페이지(JS)는 별도 렌더 파이프라인 게이트로 분리한다. (현재: 미구현, 정적 HTML만)

### 2.2 색인 (Index)

- TARGET-I1: 문서 변경 → 색인 반영 지연(index lag) 목표를 두고 측정한다. (현재: outbox 멱등 소비 구현, 지연 SLO 미설정)
- TARGET-I2: 삭제·비공개·법적 제거는 tombstone으로 즉시 검색 제외 + 전 경로(pg·색인·캐시·스토리지·백업 보존정책 내) purge를 검증한다. (현재: tombstone 즉시 제외 구현, 스토리지·백업 연계 검증 잔여 038·085)
- TARGET-I3: 언어별 분석기를 실측으로 고정한다. 한국어 Nori(+사용자 사전·복합명사), 영어 stemmer, 태국어 등 확장 언어는 별도 게이트. (현재: Nori·영어 분석기 검증됨 033, 사용자 사전 동적 갱신 잔여)
- TARGET-I4: blue-green alias 무중단 재색인·롤백을 운영 절차화한다. (현재: 구현됨 035, 운영 스냅샷 094 잔여)

### 2.3 검색 서빙 (Serving)

- TARGET-S1: 대표 쿼리셋·부하 조건을 고정한 지연 SLO를 둔다. 마스터 게이트 p95 ≤ 500ms를 1차 목표로, 규모 확장 후 p95 ≤ 200ms를 지향한다. (현재: 소규모 로컬 측정만)
- TARGET-S2: 부분 실패는 fail-closed(503 + 원인 분류)로 처리하고 빈 성공으로 위장하지 않는다. (현재: 구현됨 G001, `/readyz` 503+원인 B-2)
- TARGET-S3: 예산 소진·제공자 장애 시 degraded 폴백(자체 결과 + 제한 안내)을 표준 동작으로 둔다. (현재: hybrid 예산 폴백 구현됨)
- TARGET-S4: 가용성 월 99.9% 목표 + 에러버짓 소진 시 트래픽 제어. (현재: SLO 계산 코드 096, 운영 연동 잔여)

### 2.4 관련도·랭킹 (Relevance)

- TARGET-R1: 수천 질의 규모의 인적 판정셋(의도·언어·버티컬 층화, 이중 블라인드, κ ≥ 0.70)을 구축한다. ([평가 가이드](QUALITY_EVALUATION_GUIDE_KO.md) 절차 준용, 현재 12질의 toy 골든)
- TARGET-R2: NDCG@10·MRR@10·zero-result율·클릭편향 보정 지표를 릴리스 게이트로 둔다. (현재: 계산기 구현 046, 게이트 데이터 없음 050 차단)
- TARGET-R3: BM25 베이스 → 하이브리드 회수(어휘+fuzzy/phrase, 현재 C-6) → 벡터 회수(현재 k-NN seam만, 임베딩 BLOCKED) → LTR 순서로 단계 고도화하고 각 단계를 A/B로 검증한다.
- TARGET-R4: 스팸·어뷰즈(키워드 스터핑·링크팜·클릭 조작) 탐지를 오프라인 평가셋으로 회귀 관리한다. (현재: 휴리스틱 구현, 대규모 평가셋 없음)
- TARGET-R5: 신선도·권위·지역성·의도별 블렌딩 가중치를 실험 플랫폼(결정적 할당·오염 방지·롤백)으로 튜닝한다. (현재: 실험 코드 in-memory 049, 영속화 잔여)

### 2.5 쿼리 이해·UX (Query & SERP)

- TARGET-Q1: 오타·초성·자모·띄어쓰기·한영 전환 교정과 자동완성을 색인·로그 기반으로 제공한다. (현재: 색인 기반 교정·완성 C-4, 초성·대규모 로그 기반 잔여)
- TARGET-Q2: 자동완성·인기어 어뷰즈(PII·조작·유해어) 필터를 영속 정책으로 운영한다. (현재: in-memory 042, 영속화 잔여)
- TARGET-Q3: SERP는 제목·URL·스니펫·출처·날짜를 일관 계약으로 제공하고, 외부 공급원 결과는 공급원을 표시한다. (현재: `{title, url, description, source}` 계약, 제공자 식별 표시는 V-02 후속)
- TARGET-Q4: 접근성(WCAG 2.1 AA)·반응형·다국어를 릴리스 게이트로 둔다. (현재: 상용화 검증에서 부분 통과, 대비 수치·전수 잔여)

### 2.6 수직검색 (Verticals)

개방 순서 원칙: 권리 확보가 빠른 버티컬부터, 버티컬마다 **수집→색인→표시→삭제** 전 경로 게이트를 통과해야 개방한다.

- TARGET-V1: 뉴스 — 제휴·RSS/API 수집 + 요약 길이 상한 + 정정·삭제 15분 SLA. (현재: 코드 뼈대, 계약 없음 F-3)
- TARGET-V2: 이미지 — 라이선스·썸네일·출처·안전분류. (현재: 뼈대 051·052)
- TARGET-V3: 쇼핑 — 판매자 피드·가격 신선도·제휴(`광고`) 표기. (현재: 뼈대 058)
- TARGET-V4: 지도·장소 — 라이선스 지리데이터 + POI 정정 절차. (현재: 뼈대 056·057)
- TARGET-V5: 동영상 — 메타 + 허가 임베드. (현재: 뼈대 053)

### 2.7 AI 답변 (AI Overviews)

- TARGET-A1: 허용 문서(`robots_indexable` + 라이선스 확인)만 근거로 사용하고, 출처 URL·시점을 인용한다. (현재: 코드 구현, 모델 미연동)
- TARGET-A2: 충실도(인용 정밀도·재현율)·환각률·프롬프트 인젝션 차단을 평가셋으로 게이트한다. (현재: 가드레일 단위테스트, 실측 잔여)
- TARGET-A3: 근거 부족·신뢰도 미달·YMYL 고위험은 일반 검색 fallback + 면책을 강제한다. (현재: fallback 로직 구현 068)
- TARGET-A4: 모델·비용 상한(쿼리당·일별)을 두고 초과 시 차단한다. (현재: 텔레메트리·원장 구현 069)

### 2.8 광고·수익 (Ads)

- TARGET-D1: 오가닉과 완전 분리된 경매·점수·슬롯 + `광고`/`Sponsored` 필수 표기. (현재: 코드 분리 구현, 슬롯은 빈 배열 A-1)
- TARGET-D2: 부정클릭·봇·어뷰즈 무효화 + 복식부기 원장 + 대조(reconciliation) 불일치 제로. (현재: 코드 구현, 영속·대조 운영 잔여)
- TARGET-D3: 실결제는 샌드박스 통과 + 이중승인 + 독립 감사 후에만. (현재: 차단 유지 080, F-4·F-5)

### 2.9 개인정보·안전 (Privacy & Safety)

- TARGET-P1: SafeSearch 3단계의 분류 정밀도·재현율을 언어별 평가셋으로 측정한다. (현재: DSL 필터 구현 C-5, 분류 성능 평가 전)
- TARGET-P2: 검색어·로그 최소 수집 + k-익명성 + 보존기간·파기 자동화. (현재: 부분 구현 084·085)
- TARGET-P3: DSAR(열람·정정·삭제·이동·철회) 접수→실행→검증 파이프라인을 운영화한다. (현재: 상태머신 구현, 영속·UI 잔여)
- TARGET-P4: 신고→심사→takedown→이의신청 플로우를 운영 콘솔과 연계한다. (현재: API·큐 구현, 콘솔 잔여)

### 2.10 운영·출시 (Ops & Launch)

- TARGET-O1: 로그·메트릭·트레이스 + SLO/에러버짓 + 경보 + 인시던트 대응. (현재: /metrics·경보 규칙 존재, 운영 연동 잔여)
- TARGET-O2: 백업·복원 리허설(RTO/RPO 실측)을 분기 게이트로 둔다. (현재: 절차서 존재, 운영 DB 실드릴 잔여)
- TARGET-O3: 카나리(1%→5%→25%→100%) + 30초 롤백 + 결함 제로(P0/P1) 게이트. (현재: 계획·평가기 구현, 실운영 잔여)
- TARGET-O4: 독립 감사(보안·법무·정산·품질) 서명 후 공개 전환. (현재: F-4 BLOCKED)

## 3. 갭 해소 로드맵 (기존 100작업 + 후속)

| 순서 | 작업 | 연결 |
|---|---|---|
| 1 | 제공자 어댑터 추상화 + 국내/글로벌 축 확정 | R-01 권고, [제공자 전략](SEARCH_PROVIDER_STRATEGY.md) |
| 2 | 인적 판정셋 구축 + NDCG/MRR 릴리스 게이트 운영화 | G022, 045·046·050 |
| 3 | 실험 플랫폼 영속화 + RRF·가중치 A/B | G020, 049 |
| 4 | 벡터 회수(임베딩) + LTR 단계 도입 | C-6 후속, 047 |
| 5 | 어뷰즈·스팸 영속 정책 + SafeSearch 평가셋 | 042·044 |
| 6 | 실규모 부하·용량·DR 실측 | 048·091~094 |
| 7 | 버티컬 순차 개방 (V1→V5) | 051~060, F-3 |
| 8 | AI 제한 공개 (SLA·면책 후) | 061~070, F-3 |
| 9 | 광고·정산 활성화 (감사 후) | 071~080, F-4·F-5 |
| 10 | SLO 운영 + 카나리 + 독립 감사 | 096·098~100, F-4 |

외부 승인 트랙(F-1~F-5)은 코드와 병렬로 사업 소유자가 추진한다. 승인 없이 결제·공개 크롤·공개 출시를 활성화하지 않는다.

## 4. 금지事项 (변경 없음)

- Google·네이버·Bing의 상표·로고·독점 UI·비공개 코드·랭킹 공식 복제 금지.
- Google SERP 무단 스크래핑·접근 우회 금지 (Google Custom Search JSON API는 신규 판매 종료, 2027-01-01 서비스 종료 예정 — 대체재가 아님).
- 달성하지 못한 수치를 달성 수치로 보고 금지. 목표와 실측을 구분 표기한다.
