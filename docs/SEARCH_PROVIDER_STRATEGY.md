- 선택기: `SEARCH_PROVIDER` 1개 (`opensearch`·`local`·`brave`·`hybrid`, 기본 `opensearch`).
  `bing` 지정 시 부팅 거부 (Bing Search API 2025-08-11 퇴역).
- `brave`: Brave `/res/v1/web/search` 단독 (키 + `BRAVE_API_TERMS_APPROVED=true` 필요, page ≤ 10).
- `hybrid`: 자체 + Brave 병렬 호출 후 인메모리 RRF 병합 (page ≤ 10, `total: null`).
- 그 외: `SEARCH_BACKEND_URL` 자체 백엔드 (OpenSearch BM25+Nori+하이브리드 RRF).
- 출력 계약: `{title, url, description, source}` 4필드 단일화.
- **제공자 추상화 도입됨 (RV-01 DONE, 2026-11-24. 이하 11-11 서술은 폐기)**: `gateway/providers.mjs`
  레지스트리로 분리됐고, Brave 전용 분기는 제거됐다. 신규 제공자는 어댑터 1개(`fetchPage`) +
  config 승인·한도 + UI 라벨로 추가한다. 구 4점 접합·3파일 산재 서술은 과거 기록이다.

## 3. 결정: 2단계 제공자 로드맵

### 3.1 1단계 — 추상화 + 웹 축 확정 (선행)

1. **제공자 어댑터 추상화 도입** (R-01 권고, RV-01 DONE): 레지스트리·정규화·재시도·브레이커·쿼터 구현됨.
2. **웹 축 단일 후보 확정**: Mojeek(글로벌 웹) 또는 네이버(국내) 중 택1. 둘 다 전송 검증됨. live 선정 조건:
   - Mojeek: ToS 전문 재대조 + 키 live 확정.
   - 네이버: 약관 원문 대조 + 쇼핑 증거양립 해소(U-02) + M0 적용 여부 (U-03).
3. **fail-fast 행렬 재구성** (R-05-3 방향): 제공자별 필수 env × 승인 플래그, production 부팅 거부, 한도 초과 degraded 폴백 일반화, 버티컬별 가용 행렬.

### 3.2 2단계 — 글로벌 축 + 버티컬 (조건 해소 후)

1. **글로벌 축 재선정**: Serper·You.com·Brave 유지 중 택1 (Tavily 불가). Serper는 파라미터·total 키 실호출(W-03 축소), You.com은 인증·MSA 확인(W-04 부분), Brave는 storage 계약 확인(V-04-2, W-05 축소)이 각각 선행된다.
2. **버티컬 개방은 제공자 연동과 분리 착수**: 버티컬 UI·게이트 해제가 동반되므로 (R-02-2, V-01-2) 웹 교체와 별도 트랙으로 둔다.
3. **버티컬 경로 5분 메모리 캐시 처리** (V-07-2 보정): 외부 제공자 결과를 버티컬 경로로 흘릴 경우 캐시 우회·TTL 정책을 착수 조건으로 둔다.

## 4. 수용 테스트 (V-06 설계 확정)

키 발급 후 실행. 대표 쿼리 4군(국내 정보형·뉴스형·쇼핑형·영문 혼합, 각 10~15개) + 합격 기준:

- 국내 정보형 상위 10개 중 국내 사이트 비율 60% 이상
- 0건율 5% 이하 (희귀 쿼리 제외 규칙 사전 정의)
- 한글 쿼리→한글 결과 80% 이상, 영문 쿼리→영문 결과 70% 이상
- 동일 URL 중복 0건, 성인·스팸 혼입 0건
- p95 3초 이내 (게이트웨이 8초 타임아웃 이내)

동일 쿼리셋을 제공자별로 blind 병렬 평가하고, 기준 충족 수 + 비용(크레딧·한도) 행렬로 선택한다. 버티컬 테스트 시 5분 캐시를 우회·무효화한다.

## 5. 미해결 추적 (GAP_REGISTER 연계)

- U-01: SE-02 fail-fast 매트릭스 실물 (M0 원문 확보 후 대조)
- U-02: 네이버 쇼핑 API 존속 여부 (공식 확인)
- U-03: 네이버 약관 원문 (조항·캐시 범위·M0 적용)
- U-04: OLMOA·getfortrip 상품 스펙 (언급 0건)
- U-05: Common Crawl 한국어 선별 규모·기간 (별도 산정)
- W-01: report.md·Serper 착수안 원문 (전달 시 보완 대조)
- W-02 해소(Mojeek 구현) / W-03 축소(파라미터·total 잔여) / W-04 부분(offset 확인, 인증·MSA 잔여) / W-05 축소(표기 구현, 로고·전문 잔여). 상세는 GAP 등록부.

## 6. 금지·경계

- 네이버 개정 약관의 결과 페이지 광고 금지·수익 금지는 결과 페이지 광고 수익 모델과 정면 충돌 가능성이 있어, 수익화 위치 확정 없이는 상용 전환 불가 (R-07-1).
- Mojeek 결과를 자체 색인으로 편입하는 흐름 금지 (약관 §1.8.3 경계, 현 코드에 해당 흐름 없음 V-01-3).
- 외부 결과의 DB·파일·캐시 저장은 제공자별 약관 대조 후에만 (웹 경로 현재 저장 없음, 버티컬 5분 캐시 주의).
