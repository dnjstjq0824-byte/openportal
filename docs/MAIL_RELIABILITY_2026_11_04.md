## 재현과 수정

| 문제 | 재현 근거 | 수정 |
|---|---|---|
| 발송 결과가 불명확한 메일을 새 임시메일 ID로 교체 가능 | 새 통합 테스트에서 409를 기대했으나 기존 코드가 200을 반환해 실패했다. | 발송 예약이 있으면 임시메일 교체를 거부한다. 화면도 불확실한 발송의 재시도와 편집을 차단한다. |
| 저장과 발송의 경쟁 상태 | 동일 계정/메일 ID에 동시에 저장·발송이 들어올 수 있었다. | 두 작업에 공통 PostgreSQL advisory lock을 사용한다. 잠금 중인 작업은 409로 거부하고 잠금 해제도 회귀 검사한다. |
| 이전 메시지 응답이 현재 선택을 덮어쓸 수 있음 | 읽기 요청에 순서·취소 처리가 없었다. | 목록/본문 요청에 별도 순서와 AbortController를 적용하고 선택 변경·언마운트 시 취소한다. |
| 읽음 처리 도중 다른 메시지 상태 변경 가능 | 비동기 처리 후 전역 선택 객체를 다시 참조했다. | 요청 당시 메시지 객체와 ID를 유지하며 현재 요청일 때만 화면 상태를 바꾼다. |
| 임시메일 변경의 실수로 인한 폐기 | 폴더 변경·다른 메일 선택·취소 또는 앱 이동 시 바로 작성 화면을 닫았다. | 메일 내부 이동과 앱 링크·뒤로 가기에 폐기 확인을 적용했다. 취소하면 작성 내용과 현재 경로를 유지한다. 브라우저 새로고침/종료도 경고한다. |
| 날짜 형식 오류로 화면 렌더링 실패 가능 | 공급자가 유효하지 않은 날짜를 반환하면 DateTimeFormat이 예외를 던질 수 있었다. | 유효성을 검사하고 로케일별 대체 문구를 표시한다. |
| 한국어·태국어 화면에도 From 표시 | 조건식이 항상 영어 분기를 선택했다. | 한국어·태국어·영어 발신자 라벨을 중앙 번역 리소스로 옮겼다. |
| 모바일 폴더 목록이 읽기 공간을 과도하게 차지 | 모바일 화면을 실제 렌더링해 확인했다. | 모바일 폴더 메뉴를 가로 스크롤로 정리했다. |

잠금은 계정 ID와 메일 ID를 함께 사용한다. 잠금을 잡은 연결에서 후속 쿼리도 실행해 다중 요청 시 DB 연결 풀 고갈로 서로 기다리는 상황을 피한다. 스키마 변경은 없다.

## 검증 근거

| 실행 | 결과와 범위 |
|---|---|
| `npm.cmd run test:platform` | 수정 후 27개 통과. 실제 임시 PostgreSQL, loopback SMTP, JMAP/ClamAV 프로토콜 모의 서버 사용. 불확실한 발송의 임시메일 교체 차단, 공통 잠금·해제, 기존 인증/소유권/첨부 검사 포함. |
| `npm.cmd run test:mail:e2e` | PC 1440px와 모바일 에뮬레이션 390px에서 총 8개 통과. 순서가 뒤바뀐 응답 무시, 새로고침 후 불확실한 발송 재시도 차단, 임시 저장·재열기, 앱 링크·뒤로 가기에서 폐기 거부, 검색 URL 상태 회귀 검사. |
| `npm.cmd run typecheck --prefix apps/web` | 통과. |
| `npm.cmd run build --prefix apps/web` | 통과. 최종 번들 생성 완료. 배포는 하지 않았다. |
| `cd backend; go test ./...` | 통과. 캐시를 사용한 패키지 결과 포함. |

메일 화면의 320/375/390/430/768/1024/1440/1920px 가로 넘침 검사도 통과했다. 검색 URL 회귀 검사는 브라우저 라우팅만 분리 검증하기 위해 API 응답을 모의했으며 실제 웹 검색 검증이 아니다. 모의 JMAP 발송 수락과 실제 외부 수신함 도착은 다르며, 이번 검증은 외부 이메일 송수신 성공을 의미하지 않는다.

## 남은 항목과 판정

- 실제 SMTP/JMAP 자격증명, 개인 메일함, 도메인/DNS, 실제 ClamAV와 외부 메일 발신·수신 검수: **BLOCKED / 미검증**.
- 불확실한 발송의 자동 제공업체 상태 대조 및 운영자 복구 UI: **미구현**. 안전한 수동 대조 절차는 [실행 안내](MAIL_GATEWAY_RUNBOOK.md)에 기록했다.
- 모든 메일 제공업체 호환성, Safari/Firefox·실기기, 독립 침투검사·백업 복구·운영 부하 시험: **이번 작업에서 검증하지 않음**.
- 앱 내부 링크 및 뒤로 가기의 미저장 메일 보호는 **로컬 브라우저 검증 완료**. 운영 브라우저·실기기 검수와는 구분한다.
- 86테이블 기본 SQL 스키마 및 100개 작업 계획: **변경하지 않았으며 전체 완료의 근거로 사용하지 않음**.
- 전체 서비스 출시 판정: **NO_GO**. 이번 메일 결함 수정에 대한 로컬 검증과 상용 서비스 승인은 별개다.
