# OpenScanner 검색엔진 기본 기반 — 2026-11-04

## 범위와 판정

사용자 지정 플랫폼명은 **OpenScanner**다. 이번 범위는 기존 검색·계정·메일 소스를 보존하면서 일반 웹 검색의 기본 경로를 연결하고, 로그인·회원가입과 검색을 실제 브라우저에서 검증하는 것이다.

**로컬 개발 기반 검증: 통과. 전체 글로벌 서비스 출시: NO_GO.** 네이버·다음 대비 우위나 전체 웹 검색 커버리지를 입증한 결과는 없다. 작은 개발 데이터셋의 동작 검증과 시장 경쟁력은 구분한다.

- 시작 HEAD: `9cacaad` (`style(brand): align scan illustration with the lens + beam logo`), 시작 작업 트리 깨끗함.
- 이 보고서의 기능 판정은 로컬 검증 기준이다. 저장소 push·Cloudflare 배포 결과는 해당 커밋과 CI 실행 상태에서 별도로 확인하며, 배포 자체를 상용 서비스 준비 완료로 간주하지 않는다.
- 86테이블 기본 SQL 스키마와 100개 작업 계획은 변경하지 않았다. 기존 마이그레이션 001~013을 임시 PostgreSQL에 적용한 사실은 각 기능의 운영 완료를 뜻하지 않는다.

## 구성

```text
브라우저 /ko, /th, /en
  → Vue 검색·인증·메일 UI
  → Node 웹 게이트웨이 /api/v2
      → Go 검색 API /api/v1/search
          → OpenSearch 검색 색인
      → PostgreSQL 계정·세션·요청 제한
      → SMTP 복구 이메일
      → JMAP 메일함 제공업체
```

검색의 기본 공급원은 **자체 운영 OpenSearch 색인**이다. 정식 외부 검색 API는 별도 설정으로 선택하며, 그 결과를 자체 크롤링 결과로 표시하지 않는다. 현재 로컬 색인에는 개발·예시 문서가 포함되어 있으므로 화면에서 개발용 색인임을 안내한다.

## 실제 구현과 수정

| 영역 | 구현·검증 내용 |
|---|---|
| 검색 화면 | Enter 실행, 검색 버튼, 검색어 유지, 공유 가능한 로케일 URL, 새로고침·뒤로/앞으로 이동, 결과 제목/원문 링크/설명, 다음 페이지, 로딩·빈 결과·오류 상태. |
| 다국어 | 한국어·태국어·영어 직접 접속과 언어 전환. 외부 결과 내용은 자동 번역했다고 주장하지 않는다. |
| 검색 결과 병합 | URL 쿼리 문자열이 다른 문서를 서로 다른 결과로 유지한다. 같은 공급원의 중복 결과는 중복 점수를 주지 않는다. |
| 통합 검색 | 외부 공급원의 다음 페이지 여부를 보존한다. 여러 공급원의 겹침을 모르므로 결합된 전체 건수를 임의로 만들지 않는다. |
| 장애·비용 | 하이브리드 검색에도 외부 API 전역 일일·초당 예산을 적용한다. 예산 소진 시 외부 호출을 중단하고 로컬 결과와 제한 안내를 제공한다. |
| 응답 안전성 | 검색 공급원 JSON에 크기 제한과 형식 검사를 적용하고, 내부 오류를 사용자에게 원문 그대로 노출하지 않는다. |
| 데이터 출처 | 기본값 `SEARCH_CORPUS_KIND=development`. 검토된 웹 색인 표시에는 운영자의 출처·권리 검토 설정이 필요하다. 이 설정 값 자체가 검토 증명은 아니다. |
| 크롤링 경계 | 공개 사이트 목록을 자동 승인하지 않는다. `CRAWL_ALLOWED_HOSTS`에 명시적으로 승인된 도메인을 설정해야 시작할 수 있다. 국제 도메인명은 IDNA로 정규화하며 기존 robots·SSRF 검사를 유지한다. DB 접속 문자열을 로그에 출력하지 않는다. |
| 가입 화면 | 첫 단계에서 실제 메일함 생성 기능 준비 상태를 확인한다. 서비스 미설정 시 안내·재시도를 표시하고 불필요하게 마지막 단계까지 입력하게 하지 않는다. |
| 가입 검증 | UTF-8 길이 제한을 클라이언트와 서버에서 일치시키고, 양력 연도 안내와 접근성 진행 상태를 제공한다. 불완전한 성공 응답을 계정 생성 완료로 표시하지 않는다. |
| 디자인 | 기존 OpenScanner 브랜드와 렌즈·스캔 로고를 보존한다. 로그인·회원가입의 동일한 카드·폼·탭·안내, 모바일 배치, 3개 언어 화면을 검수했다. |

기존의 공개 Bing Search API 연결은 종료된 서비스에 요청하지 않도록 차단했다. 종료 근거는 [Microsoft 공식 공지](https://learn.microsoft.com/en-us/lifecycle/announcements/bing-search-api-retirement)다. 선택형 Brave API의 페이지 제한은 [공식 API 문서](https://api-dashboard.search.brave.com/api-reference/web/search/get)를 기준으로 적용했다. 이번 작업에서 유료 외부 API 호출이나 서비스 계약은 수행하지 않았다.

## 실행과 검수

현재 로컬 개발 화면:

- 검색 홈: `http://127.0.0.1:5173/ko`
- 검색 결과: `http://127.0.0.1:5173/ko/search?q=검색엔진`
- 로그인: `http://127.0.0.1:5173/ko/login`
- 회원가입: `http://127.0.0.1:5173/ko/signup`
- 기존 로컬 Go 검색 API: `127.0.0.1:8080`
- 로컬 OpenSearch: `127.0.0.1:9200`

현재 연결된 `documents_v2`에는 문서 13개가 있었고, `검색엔진` 요청에 HTTP 200과 결과 8개가 반환되는 것을 확인했다. 이 문서 수와 결과는 기존 개발 색인 기준이며 실제 웹 전체의 크기·권리·최신성을 검증한 것은 아니다. 기존 색인 데이터는 덮어쓰지 않았다.

재현 명령:

```powershell
# 기본 웹·게이트웨이 설정은 MAIL_GATEWAY_RUNBOOK.md 참고
npm.cmd run typecheck --prefix apps/web
npm.cmd run build --prefix apps/web
node --test tests/gateway-search.test.mjs tests/translations.test.mjs
npm.cmd run test:platform
npm.cmd run test:foundation:e2e
```

Go 검사는 `backend`에서 `go test ./...`를 실행한다. `test:foundation:e2e`에는 실행 중인 로컬 OpenSearch가 필요하다. 테스트는 화면을 보고 있는 5173/8090 서버와 충돌하지 않도록 **5175/8094/8084**와 격리 PostgreSQL **55445**를 사용한다. 전용 이름의 임시 색인만 생성·정리한다.

SMTP·DB·JMAP 설정과 검수 계정 절차는 [게이트웨이 실행 안내](MAIL_GATEWAY_RUNBOOK.md)에 있다. 실제 메일함 생성 제공업체 어댑터는 아직 기본 CLI에 연결되지 않아, 운영 가입을 임의 활성화하지 않는다.

## 검증 증거

| 명령·검사 | 결과 | 범위 |
|---|---|---|
| `node --test tests/gateway-search.test.mjs` | 7개 통과 | 공급원 전송을 모의한 검색 병합·페이지·종료 API 차단 검사. 실제 외부 API 성공 증거가 아니다. |
| `npm.cmd run test:platform` | 31개 통과 | 실제 임시 PostgreSQL·loopback SMTP, 메일/JMAP·검사기·외부 검색 공급원은 프로토콜 모의. |
| `npm.cmd run test:foundation:e2e` | PC/모바일 총 6개 통과 | 실제 브라우저 → 게이트웨이 → Go → OpenSearch 경로, 합성 검색 문서, 실제 로컬 계정·세션·SMTP. JMAP/메일함 생성은 모의 제공업체. |
| 언어·해상도 | 통과 | 한국어·태국어·영어 로그인/회원가입, 320/375/390/430/768/1024/1440/1920px 가로 넘침 검사. 모바일은 에뮬레이션이다. |
| `go test ./...` | 통과 | 크롤러의 명시적 허용 목록, 국제 도메인명 정규화 및 기존 Go 회귀 검사 포함. 외부 크롤링은 실행하지 않았다. |
| 웹 타입 검사 | 통과 | Vue/TypeScript 검사. |
| 웹 프로덕션 빌드 | 통과 | Vite 빌드. 실제 운영 API 연결 증거는 아니다. |
| 검색·Pages·번역 회귀 검사 | 19개 통과 | 로컬 Node 검사. 원격 CI 성공을 의미하지 않는다. |

최종 크롤러 점검에서 직접 URL의 동적 호스트 등록을 제거했다. 직접 URL과 기존 DB 큐 모두 현재 허용 목록의 HTTPS 443 호스트만 처리하며, 실행당 최대 처리량은 기본 20개(`-max-pages`, 최대 10000개)다. 외부 수집은 실행하지 않았다. Cloudflare 배포 워크플로의 토큰 존재 판정을 작업 환경으로 옮겨, 토큰이 설정된 경우 publish 조건에서 확인할 수 있게 했다. 운영 메일함 생성 어댑터와 실제 공개 검색 인프라는 여전히 별도 설정·검증 대상이다.

새 회귀 테스트는 수정 전에 URL 쿼리 문자열 손실, 잘못된 통합 건수, 가입 준비 상태 누락을 실패로 재현했다.

## 성능 측정의 범위

동일한 Windows 로컬 호스트에서 합성 문서 13개가 일치하는 검색을 20회, 동시성 2로 측정했다. 브라우저의 PC/모바일 프로젝트는 같은 장비에서 실행했으며 모바일 하드웨어 성능 비교가 아니다.

| 실행 | p50 | p95 | 실패 |
|---|---:|---:|---:|
| PC 프로젝트 실행 | 29.87ms | 115.60ms | 0/20 |
| 모바일 에뮬레이션 프로젝트 실행 | 20.22ms | 34.62ms | 0/20 |

원본: [PC 지연 시간](evidence/foundation/desktop-search-latency.json), [모바일 프로젝트 지연 시간](evidence/foundation/mobile-emulation-search-latency.json). 이 수치는 운영 부하, 글로벌 네트워크, 큰 색인, 사용자 동시 접속에 대한 성능 보장이 아니다.

## 글로벌 검색으로 확장하기 위한 필수 조건

1. 소유·수집 권리가 확인된 사이트·피드·문서 집합을 확보하고 출처, 삭제·갱신 정책을 관리한다. 임의 도메인 수집을 시작하지 않는다.
2. 한국어·태국어·영어 실제 평가 질의와 인적 관련도 판단을 확보해 NDCG/MRR, 빈 결과 비율, 언어별 형태소 분석 품질을 측정한다. 합성 입력 통과로 검색 품질 우위를 선언하지 않는다.
3. 허용된 실제 데이터 규모를 늘려 색인 갱신·삭제 전파·재색인·복구와 부하를 검증한다.
4. 외부 검색 API를 쓰면 정식 계정·약관·표시/저장 제한과 비용 승인을 확인한다. 공급원별 실패·예산·할당량을 모니터링한다.
5. 메일함 생성 어댑터, 실제 SMTP/JMAP·도메인 DNS·악성코드 검사기와 외부 발신/수신을 별도 검증한다. 개발용 `.test` 메일 주소는 공개 이메일 서비스가 아니다.
6. 독립 보안·개인정보·법률 검토, 백업 복구, 스테이징 전체 흐름과 운영 승인 후 배포한다.

현재 확보한 것은 실제로 실행·검증할 수 있는 **로컬 검색·계정 기본 경로**다. 전체 웹 커버리지, 독립 품질 평가, 대규모 운영 및 경쟁사 대비 우위는 미검증으로 남긴다.
